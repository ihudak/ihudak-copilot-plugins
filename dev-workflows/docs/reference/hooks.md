# Hooks reference

`dev-workflows` bundles 4 hooks, declared in `hooks/hooks.json` and installed automatically with the plugin — there is nothing to opt into separately. Every hook is advisory: **a hook never blocks Copilot.** All four scripts end in an unconditional `exit 0` regardless of what they detect or whether their own logic errors out, by contract — a hook exists to notify or remind, never to gate a tool call.

**Copilot CLI has no `matcher` field.** Claude Code's `hooks.json` can restrict a `PostToolUse` hook to a specific tool (`matcher: "Bash"`, `matcher: "Edit|Write"`); Copilot CLI's hook schema has no equivalent. `hooks.json`'s own `_comments` block states this outright: both of this edition's `PostToolUse` hooks fire on **every** tool use, not just the one they care about, so each script's own first job is to return fast and exit 0 for an invocation it does not care about. `test-notify.sh` returns unless the command is a test runner; `changelog-owners-reminder.sh` returns unless the edited file is a dynatrace-docs `.md` content page. The Claude-edition page for this plugin carries no such note, because that edition's `matcher` field does the filtering before the script ever runs.

| Hook | Event | Fires on | What it does |
|---|---|---|---|
| `notify-done` | `Stop` | every turn | Raises a cross-platform desktop notification, "Copilot finished", at the end of every turn. |
| `preload-context` | `UserPromptSubmit` | every submitted prompt | On a matched `implement:`/`document:`/`epics:`/`release-notes:`/`vuln:`/`upgrade:` prompt (keyword or `/slash` form), injects git/model-routing/Jira context; a near-instant no-op otherwise. |
| `test-notify` | `PostToolUse` | **every tool use** (no matcher — self-gates in-script) | Detects a test-runner invocation, parses its pass/fail counts, and raises a desktop notification summarizing the result. |
| `changelog-owners-reminder` | `PostToolUse` | **every tool use** (no matcher — self-gates in-script) | On a tracked dynatrace-docs content page, warns if today's changelog entry or required `managed/` owners are missing. |

## What each hook does, in detail

### `notify-done` (`hooks/notify-done.sh`)

Runs on every `Stop` event, so it fires at the end of every turn regardless of what happened during it. It builds one fixed message, `"Copilot finished"`, and dispatches it through the first notification mechanism available for the host: `osascript` (title "GitHub Copilot") when `$OSTYPE` starts with `darwin`, `wsl-notify-send` or a PowerShell balloon-tip fallback when `/proc/version` mentions Microsoft (WSL), and `notify-send` — falling back to a plain terminal bell (`echo -e '\a'`) if that binary is missing — everywhere else. Every branch degrades to a fallback rather than propagating a failure — the darwin branch is explicitly suffixed `|| true`, while the WSL and default branches instead fall through to `echo -e '\a'` (a terminal bell) when their own notifier command fails; the actual never-fails guarantee comes from the unconditional `exit 0` on the script's last line, regardless of which branch ran. It carries no `python3` guard, because it never calls `python3` at all.

### `preload-context` (`hooks/preload-context.sh`)

Runs on every `UserPromptSubmit` event. It first guards on `command -v python3`, exiting immediately when python3 is absent (line 29). It then reads the submitted prompt from stdin JSON (trying the `prompt`, `user_prompt`, and `message` keys in turn for compatibility across CLI versions) and matches it against `^/?(implement|document|epics|release-notes|vuln|upgrade):?[[:space:]]+[^[:space:]-]` — a recognized command name, in **either** the plugin's own keyword form (`implement: <arg>`) **or** the CLI's bare `/slash` form (`/implement <arg>`), followed by at least one non-flag argument. Anything else, including a bare command with no argument, exits immediately with no output. For a match, it routes by command: `implement:`, `vuln:`, and `upgrade:` get full context (a model-routing reminder pointing at the bundled `skills/_shared/model-routing.md`, the current branch, `git status --short`, the last 5 commits, and a directory listing when the cwd has 30 or fewer entries), plus Jira context (`$VAULT_PATH`, `$REPOS_PATH` default, `$SPECS_PATH`, and the current branch) when `implement:`'s own argument looks like a Jira ID; `document:` gets Jira context only when its argument looks like a Jira ID, since its free-text/`@file` direct-edit mode owns its own git hygiene and never invokes the strong-reasoning tier; `epics:` and `release-notes:` always get Jira context, since both are Jira-driven and accept either a Jira ID or an imported-Jira directory. `docs-profile:` and every other command are not matched at all, so no context is injected for them. An unmatched `cmd` inside the routing `case` falls to a `*)` branch that is unreachable given the regex above — it exits silently, guarding against a future widening of the match regex rather than anything reachable today.

### `test-notify` (`hooks/test-notify.sh`)

Runs on **every** `PostToolUse` event — Copilot CLI has no tool matcher, so this fires after every tool call, not only `bash`. It first guards on `command -v python3`, exiting immediately when python3 is absent (line 6). It reads the tool-call payload from stdin, extracting the executed command and its captured output (checking both the nested `tool_input`/`tool_response` shape and top-level fallback keys for older payload versions) — for a non-`bash` tool call this simply extracts an empty command string. If the command does not match one of `mvn test`, `gradlew test`, `gradle test`, `npm test`, `yarn test`, `pytest`, or `make test`, it exits immediately — the self-gate the missing matcher makes necessary. For a match, a small embedded Python script parses tool-specific pass/fail counts out of the output — `Tests run:`/`Failures:`/`Errors:` for Maven, `N tests completed, N failed` for Gradle, `N passed, N failed` for pytest, and a `Tests: … passed … failed` line for npm/yarn — falling back to the literal string `"tests completed"` when no pattern matches, and raises a desktop notification (the same cross-platform dispatch as `notify-done`, title "GitHub Copilot") reading `"Test run: <summary>"`.

### `changelog-owners-reminder` (`hooks/changelog-owners-reminder.sh` + `changelog-owners-reminder.py`)

Runs on **every** `PostToolUse` event, for the same no-matcher reason as `test-notify`. The shell script is a thin dispatcher: it first guards on `command -v python3`, exiting immediately when python3 is absent (line 9); otherwise it resolves `$PLUGIN_ROOT` (falling back to the script's own parent directory if the variable is unset, which happens outside a normal plugin invocation) and hands the tool payload straight through, on stdin, to `changelog-owners-reminder.py`. The Python script does the actual check — and the self-gate: it reads the edited file's path from the payload's `tool_input.file_path` key and returns immediately unless the path ends `.md` and contains `/dynatrace/_content/` or `/managed/_content/` (the two dynatrace-docs content roots), which for any tool call that carries no `file_path` at all — most non-editing tool calls — is empty and returns at once. For a matching page it re-reads the file's own frontmatter and checks two things independently: a changelog gap is only flagged when `git status --porcelain` also shows the file as tracked-and-modified (so a brand-new untracked file is not yet expected to carry a changelog entry) and the frontmatter's `changelog:` block has no entry dated today; a `managed/`-rooted page is additionally checked, regardless of its git status, for whether its `owners:` block includes every name listed in the plugin's bundled `skills/_shared/dynatrace-docs/managed-owners.txt`. Any gap becomes one line in a `{"systemMessage": ...}` reminder naming the file, the specific issues found, and pointing at `skills/_shared/dynatrace-docs/changelog-guidelines.md` and `managed-owners.txt` to fix them — the `dynatrace-docs-frontmatter` skill those files back is not bundled in this edition (see below), so the message points at the guideline files directly instead of at a skill this edition cannot run; a page with no gaps prints nothing.

## Why none of this blocks you

Every script above ends `exit 0` unconditionally — the exit code is never derived from what the hook found, so a missing notifier binary, an unparsed test-output format, or a page failing the changelog/owners check never stops a tool call, a turn, or the run itself. Three of the four also guard on `command -v python3` up front and exit 0 immediately when it is absent, degrading to silence rather than failing — `preload-context.sh:29`, `test-notify.sh:6`, and `changelog-owners-reminder.sh:9`; `notify-done` carries no such guard because it never calls `python3` at all. Because Copilot CLI applies no tool-level filter before a `PostToolUse` hook runs, `test-notify` and `changelog-owners-reminder` pay their self-gate check on every single tool call in a session, not only the ones they act on — a cost the Claude edition's `matcher` field avoids, but still cheap enough (a `grep`, or a JSON-key lookup) not to matter in practice. The dynatrace-docs conventions `changelog-owners-reminder` checks are covered in full, including how to satisfy them, by a `dynatrace-docs-frontmatter` skill in the canonical and mgd editions of this plugin — this Copilot edition's source files still name that skill in several places, but it was never ported here, a known gap (see [References](references.md#skills)); this page only describes what the hook itself does.
